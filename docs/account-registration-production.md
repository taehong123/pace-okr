# 회원가입 휴대전화 확인 운영 체크리스트

OKRPTR 신규 가입은 Google 로그인 뒤 휴대전화 **소유 확인**을 진행한다. 이 흐름은 실명 또는 PASS 본인인증이 아니다. 마케팅 목적 개인정보 이용과 광고성 문자 수신은 각각 선택 동의이며 가입 조건으로 사용하지 않는다.

## 1. Twilio Verify 준비

1. 운영자 명의의 Twilio 계정과 Verify Service를 만든다.
2. 한국 수신 번호로 인증 문자가 정상 도착하는지 테스트한다.
3. Sites 운영 환경에 아래 값을 보안 값으로 등록한다.

- `TWILIO_ACCOUNT_SID`
- `TWILIO_AUTH_TOKEN`
- `TWILIO_VERIFY_SERVICE_SID`
- `ACCOUNT_DATA_ENCRYPTION_KEY`: 기존 OAuth 키와 다른 충분히 긴 무작위 값

## 2. 안전한 활성화 순서

1. 코드와 `0032_account_registration.sql`을 먼저 배포한다.
2. 마이그레이션이 기존 사용자를 `legacy` 가입자로 이관했는지 확인한다.
3. 위 네 보안 값을 등록한 뒤 운영 환경에서 테스트 신규 계정으로 문자 발송과 확인을 검증한다.
4. 마지막에 `ACCOUNT_REGISTRATION_REQUIRED=true`를 등록한다.
5. 새 Google 계정은 가입 확인 화면으로, 기존 계정은 기존 워크스페이스로 진입하는지 확인한다.

인증 공급자 값이 없거나 기능 플래그가 `true`가 아니면 신규 가입 차단은 활성화되지 않는다. 로컬 개발 환경에서는 공급자 값이 없을 때만 `000000`을 개발용 인증번호로 사용한다.

## 3. 동의와 광고 연락

- 두 선택 동의는 기본 미선택 상태로 제공한다.
- 실제 광고 연락 대상은 `marketingEligible=true`인 사용자로 제한한다.
- 사용자가 내 설정에서 철회하면 이후 광고 발송 대상에서 즉시 제외한다.
- 광고성 정보 수신 동의 시각이 2년을 넘으면 재확인 전까지 발송 대상에서 제외한다.
- 현재 구현은 동의 상태를 저장하고 판정할 뿐, 광고 문자 발송 기능이나 연락처 내보내기 기능은 포함하지 않는다.

## 4. 배포 전 확인

- 개인정보처리방침의 Twilio 국외 이전 내용과 실제 계약·리전이 일치하는지 확인한다.
- 발신번호, 광고 표기, 야간 전송 제한과 수신거부 방식은 실제 광고 발송 도구 도입 전에 별도로 법률 검토한다.
- 운영 로그나 오류 메시지에 전화번호 원문, 인증번호 또는 Twilio 자격증명이 남지 않는지 확인한다.
- 마케팅 동의 철회, 기존 회원 이관, 요청 횟수 제한과 10분 만료를 회귀 테스트한다.
