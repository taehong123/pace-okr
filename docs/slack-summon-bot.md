# Slack 소환 봇

## 명령

```text
!테스크생성 고객 인터뷰 정리
참여자별 의견과 개선 요청을 정리합니다.
```

- `!테스크생성`, `!태스크생성`, `!task`는 같은 명령입니다.
- 첫 줄이 Task 제목, 다음 줄부터 설명입니다. 제목은 240자, 설명은 8,000자까지입니다.
- 제목 없는 생성 명령과 `!소환봇`, `!okri`는 사용법을 답합니다. 빈 Task를 생성하지 않습니다.
- `@OKRI !task Review onboarding`도 지원합니다. 다른 봇을 멘션한 명령은 무시합니다.
- 봇이 참여한 공개/비공개 채널, 해당 채널의 스레드, 봇과의 개인 DM에서 호출합니다.
- 명령은 메시지 맨 앞에 있어야 합니다. 인용, 코드 블록, 일반 대화 속 명령, 봇 메시지, 수정/삭제 이벤트는 생성하지 않습니다.
- Task는 연결된 OKRI 워크스페이스의 일반 루틴에 생성됩니다. 담당자, 프로젝트, 기한은 임의 지정하지 않습니다. 생성자는 호출한 멤버입니다.
- 결과는 원래 스레드로 보냅니다. 기존 스레드 안의 명령은 같은 스레드에 답합니다.

설정 화면: `/?settings=workspace&tab=integrations&bot=summon`.

## 프로젝트 입력창

```text
!프로젝트생성 온보딩 개선
고객의 첫 경험을 개선합니다.
```

`!project`도 같은 명령이며, 제목 없이 `!프로젝트생성`만 보내도 됩니다.

1. 호출자에게만 보이는 **속성 입력** 버튼이 도착합니다.
2. 버튼을 누르면 Slack 모달에서 프로젝트 이름, 설명, 상위 Initiative, 상태, 우선순위, 주기, 기한, DRI, 하위 업무자와 활성 사용자 지정 속성을 입력합니다.
3. 워크스페이스에 설정한 속성 기본값을 미리 채웁니다. 텍스트/숫자/선택/날짜/체크박스/멤버/여러 멤버 속성을 지원합니다. 기한이나 담당자 기본값을 지우면 비워 둔 값으로 저장합니다.
4. **생성**을 누르면 등록을 처리하고 원래 Slack 스레드에 프로젝트 링크를 보냅니다. 취소하거나 창을 여는 것만으로는 프로젝트를 만들지 않습니다.

Slack의 메시지 이벤트에는 모달을 여는 `trigger_id`가 없으므로 버튼 클릭이 한 번 필요합니다. 클릭 직후 로딩 모달을 먼저 열어 3초짜리 트리거를 사용하고, 이후 실제 속성을 불러옵니다. [Slack 모달 문서](https://docs.slack.dev/surfaces/modals/).

- Initiative와 멤버는 현재 워크스페이스에서 검색합니다. 종료된 주기나 휴지통의 Initiative는 선택할 수 없고, 프로젝트는 선택한 Initiative의 OKR 주기를 상속합니다. Initiative나 하위 Task를 임의로 만들지 않습니다.
- 추가한 선택 속성의 선택지가 100개를 넘으면 검색형 목록을 사용합니다. Slack 제한 때문에 입력 항목이 90개를 넘거나 텍스트 기본값이 3,000자를 넘는 경우에는 속성을 임의로 생략하지 않고 웹에서 입력하도록 안내합니다. 제목은 240자, 프로젝트 설명은 3,000자까지입니다.
- 입력창은 호출자의 OKRI 사용자, Slack 사용자, Slack 팀, 워크스페이스에 묶입니다. 다른 사용자, 만료된 창, 나중에 연 입력창으로 대체된 창의 제출은 거절합니다.
- 저장 직전에도 멤버 권한과 플랜 편집 권한/프로젝트 생성 한도를 검사합니다. 프로젝트, 사용자 지정 속성, 관계형 담당자, 활동 기록은 D1 배치 트랜잭션으로 함께 저장합니다. 일부 속성만 실패해 불완전한 프로젝트가 남지 않도록 합니다.
- 제출 재전송은 초안의 원자적 상태 변경으로 차단하고, 프로젝트 ID도 초안 ID로 고정합니다. 저장 성공 뒤 응답만 끊긴 경우에도 같은 프로젝트를 다시 만들지 않습니다.
- 일반 검증/저장 실패 시 입력값을 유지한 채 **속성 입력** 버튼으로 다시 열 수 있습니다. 처리 중 중단된 요청은 2분 후 다시 열 수 있습니다. 입력 초안의 유효기간은 24시간입니다. 별도 영구 실행 큐나 자동 재시도 스케줄은 아닙니다.
- `0038_slack_summon_drafts.sql`은 임시 입력 상태만 저장합니다. 워크스페이스 삭제 시 함께 삭제되며 업무 백업 대상으로 취급하지 않습니다. 신규 권한이나 이벤트 구독은 기존 소환 봇 설정에 더하여 필요하지 않습니다.

## Slack 앱 설정

코드 배포만으로 Slack 이벤트 구독이 변경되지는 않습니다. 기존 **같은 Slack 앱**의 App Manifest에 저장소의 `slack-app-manifest.yml` 변경을 적용해야 합니다. 앱이나 설치를 중복 생성하지 마세요.

1. Bot Token Scopes에 `channels:history`, `groups:history`, `app_mentions:read`를 추가합니다. 기존 scopes는 유지합니다.
2. Event Subscriptions의 Request URL은 `https://okri.ai/api/slack/events`입니다. Bot Events에 `message.channels`, `message.groups`, `app_mention`을 추가하고 `message.im`은 유지합니다.
3. Interactivity URL은 기존 `https://okri.ai/api/slack/interactions`를 유지합니다.
4. OKRI의 워크스페이스 설정 > 봇 연동에서 Owner/Admin이 **권한 업데이트**를 눌러 기존 설치를 재승인합니다.
5. 명령을 사용할 채널에 OKRI 봇을 초대합니다. 비공개 채널은 명시적인 초대가 필요합니다.
6. 계정이 연결된 멤버로 테스트 명령을 보냅니다. 미연결 멤버에게는 본인에게만 보이는 계정 연결 버튼이 표시됩니다. 연결 후 명령을 다시 보냅니다.

공식 문서: [HTTP Events API](https://docs.slack.dev/apis/events-api/using-http-request-urls/), [공개 채널 메시지](https://docs.slack.dev/reference/events/message.channels/), [비공개 채널 메시지](https://docs.slack.dev/reference/events/message.groups/), [앱 멘션](https://docs.slack.dev/reference/events/app_mention/).

기존 데일리 봇의 권한 검사는 `slackDailyScopes`를 사용합니다. 소환 봇의 새 권한이 없어도 기존 데일리 기능 자체를 중지하지 않습니다. 전체 연결 상태에는 권한 업데이트가 표시됩니다.

## 권한과 재전송

- Slack 서명 및 5분 타임스탬프 검증 후에만 처리합니다.
- 활성 멤버 연결을 조회하고 Slack 연결의 워크스페이스와 일치하는지 확인합니다. Owner/Admin/Member만 생성할 수 있습니다.
- 웹/API와 같은 `memberCanWrite` 검사를 적용합니다. 플랜의 편집자 제한으로 읽기 전용인 멤버도 생성할 수 없습니다.
- 미연결/비활성 사용자는 계정 연결이 필요하며 Viewer와 다른 워크스페이스 멤버는 생성할 수 없습니다. 연결 링크는 공개 스레드에 게시하지 않습니다.
- 일반 채널 대화는 Task 생성 처리나 이벤트 수신 기록 저장으로 넘기지 않습니다. 별도의 채널 기록 수집은 하지 않습니다. 기존 데일리 DM 처리 방식은 유지합니다.
- `slack_event_receipts`에 `slack:summon:<team>:<channel>:<message-ts>`를 원자적으로 기록해 재전송 및 `message`/`app_mention`의 중복 전달을 막습니다. Task의 `sourceRef`도 같은 키입니다.
- 삽입 뒤 활동 기록/알림만 실패했을 수 있으므로, 오류 시 이미 저장된 Task를 조회합니다. 결과가 불확실한 삽입은 반복하지 않습니다.
- HTTP ACK 후 `waitUntil`에서 처리합니다. 이는 영구 작업 큐나 exactly-once 실행 보장은 아닙니다. 워커 종료나 외부 API 장애로 생성 또는 확인 알림이 누락될 수 있습니다. 응답이 없거나 실패 안내가 오면 Task 목록을 먼저 확인한 뒤 **새 메시지**로 재시도하세요. 기존 메시지 편집은 재실행하지 않습니다.
- Slack 제목은 응답의 `plain_text` 블록에만 표시하고 링크 펼치기를 끕니다. Task 제목에 멘션 문법이 있어도 채널 전체를 호출하지 않습니다.
